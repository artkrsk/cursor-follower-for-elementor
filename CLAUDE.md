# CLAUDE.md

## Project

"Arts Cursor Follower for Elementor": a zero-runtime-dependency TypeScript cursor engine (`src/ts/` + `src/styles/`) inside a deliberately thin WordPress plugin shell (`src/php/`, `src/wordpress-plugin/`).

Single package, no unit CLAUDE.md files — this file is the whole map. Besides `src/` and `tests/ts/`: `docs/` is the VitePress site (also the browser harness), `dev/seed/` the demo-page seed behind the wp.org blueprint, `.wordpress-org/` the listing assets and blueprint, `dist/` generated output (gitignored).

- **This repo defines the contract, and the contract is now shipped.** Markup shape, class names, data attributes and defaults are whatever `core/markup.ts` and `core/options.ts` say, and Velum integrates against that — nothing upstream constrains them. But the plugin is public on WordPress.org, so a rename reaches installed sites: a changed kit control id or `arts_cursor_*` setting key silently orphans saved Site Settings, and a changed class/attribute breaks the CSS a theme wrote against it. The pre-1.0 window where the surface could move freely is closed. Change it for a reason AND say what happens to sites already on it.
- **The PHP layer is live and deliberately thin.** The main plugin file bootstraps `src/php/Plugin.php`, which prints the inline `wp_head` gate (the plugin's only front-end output — nothing is enqueued; see the loading model under Architecture), carries `window.artsCursorFollowerOptions` in that same block (inline JSON, not `wp_localize_script`), and wires the Elementor Site Settings tab + editor live bridge. It also injects a "Cursor Effects" section into a curated set of widgets (`src/php/Elementor/WidgetControls.php`; `ContainerControls.php` and `LightboxControls.php` are the one-hook siblings, `HintControls.php` the shared trait), whose values reach the engine only through channels the editor replays — see **Elementor integration — landmines** below before touching any of it. There is intentionally NO PHP markup printer — the engine builds its own DOM client-side, always: device capability gates the pointer listeners and CSS visibility, not the markup. Velum consumes the npm package (`@arts/cursor-follower`) through `link:` as a type-only dev dependency and installs the plugin independently.

## Commands

- `pnpm dev` — VitePress dev server (port 5200) for the public docs site at `docs/`, which doubles as the browser harness: the engine boots live on every page (theme `Layout.vue`), so the demo pages exercise real layout, hit-testing and the CSS state machine. `pnpm exec vitepress build docs` / `preview docs` build and serve the static site.
- `pnpm dev:plugin` — watch-compile the engine bundle + CSS into `src/php/libraries/cursor-follower-for-elementor/` and, when `DEV_TARGET` is set in `.env`, mirror the plugin into a LocalWP site.
- `pnpm build` — release build: stamps versions, bundles minified JS/CSS, stages `dist/cursor-follower-for-elementor/`, zips, runs release assertions. Stamping rewrites tracked files (plugin header, readme.txt, package.json).
- `pnpm build:library` — passive browser ESM entries and CSS in `dist/esm`, declarations in `dist/types`; separate from WordPress output and sync. Default exports consume this output; `arts-source` selects shipped TypeScript. Source Sass is `/styles.scss` (the extension avoids Sass resolution ambiguity with `/styles.css`).
- `pnpm exec tsc --noEmit` — typecheck (esbuild does not type-check)
- `pnpm test` / `pnpm test:coverage` (`pnpm exec vitest` to watch) — Vitest over `tests/**/*.test.ts`. Config is `vitest.config.ts`; the docs site's Vite config is separate, inside VitePress (`docs/.vitepress/config.mts`).
- `pnpm exec biome check .` / `biome format --write .` — Biome, scoped to `src/ts/**`, `tests/**`, the docs TS (`docs/.vitepress/**/*.ts`, `docs/demos/**/*.ts`) and root configs. SCSS goes through stylelint instead (`pnpm exec stylelint 'src/styles/**/*.scss'`, config extends the `@arts/wp-plugin-tooling` base); `.vue` files are not linted or formatted by anything.
- `vendor/bin/phpstan analyse` (`composer phpstan`) / `vendor/bin/phpcs` — PHP analysis and coding standards, after `composer install`; both are pre-push gates.
- `pnpm exec knip` / `pnpm exec fallow` — two static analyzers over the same ground (unused files, exports, dependencies; fallow adds circular-dependency and boundary passes). A bare `pnpm exec fallow` passes no subcommand, which is how fallow runs all three of dead-code + dupes + health together; `fallow dead-code` is the fast subset when only the unused-code half matters. Both exit non-zero on findings. They are deliberately redundant so each cross-checks the other; neither scans build code, which lives in `@arts/wp-plugin-tooling`.
- `pnpm test:coverage && pnpm exec fallow health --coverage coverage/coverage-final.json` — the complexity/CRAP half on *fresh* coverage. A bare `pnpm exec fallow` reaches the same analysis but never regenerates coverage: fallow auto-discovers `coverage/coverage-final.json` when it happens to be on disk, so CRAP there is computed against whatever the last `pnpm test:coverage` left behind, and silently falls back to estimation when the file is absent. The chained form regenerates coverage first and passes it in: fallow's CRAP is otherwise `static_estimated`, where a module reachable from any test file is credited with estimated coverage — a token import satisfies it and the score stops meaning anything. fallow's `--coverage` reads Istanbul-format `coverage-final.json`, which the shared config's `v8` provider emits too — the v8 provider AST-remaps into that same format. Declaring the wrong `@vitest/coverage-*` package for the configured provider fails the whole run with `MISSING DEPENDENCY`, so the devDependency and `configs/vitest.js` (in `@arts/wp-plugin-tooling`) have to agree. Findings whose cyclomatic and cognitive numbers are both under threshold are pure coverage artefacts — write the test, don't reshape the function.

**Hooks and CI.** `lefthook.yml` (wired by `package.json#prepare`, so `pnpm install` is all it takes) installs two gates. `pre-commit`: three autofixers that rewrite and re-stage the staged files (`stage_fixed`) — Biome, stylelint on `src/styles` SCSS, phpcbf on `src/php` — then typecheck; sequential, because each check has to read what the autofix produced. `pre-push`: the full Vitest run, PHPStan, phpcs. The GitHub Actions workflows are thin callers of the reusable ones in `artkrsk/wordpress-plugin-workflows`: `test.yml` (everything the hooks run, plus knip, an advisory fallow, changelog grammar, a build with a zip size budget, the WordPress.org Plugin Check against `dist/`, and a blueprint check that fails when `.wordpress-org/blueprints/blueprint.json` is stale against `dev/seed/demo-page.php` — regenerate it with `arts-wp blueprint build`), `deploy-docs.yml` (VitePress to Pages), `canary.yml` (weekly), a scheduled WordPress version checker, the release-PR pair `prepare-release.yml` (weekly, opens a `release/x.y.z` PR) and `cut-release.yml` (tags it on merge), and `release.yml`, which fires on a `v*` tag. That last one deploys to WordPress.org over SVN (`deploy_to_wordpress: true`; the SVN secrets are account-wide — see the folder CLAUDE.md).

Where a job lands: the reusable `test.yml` and `canary.yml` default `runner` to `self-hosted`; `deploy-docs.yml` defaults to `ubuntu-latest`, so the caller passes `runner: self-hosted` (its Pages-deploy job is pinned to `ubuntu-latest` regardless). The reusable `release.yml` pins `ubuntu-latest` on every job with no input to override, and the WordPress version checker is a plain `ubuntu-latest` job of our own — those are the exceptions; everything else runs on the shared Raspberry Pi (arm64), one runner service per repo. Consequences before editing a workflow: the `setup-node` / `corepack enable` / `setup-php` steps are gated on `runner.environment == 'github-hosted'` because the host already has all of it on PATH (its `pnpm` is corepack-shimmed, so `packageManager` is honoured); Plugin Check must take the cross-repo wp-env host lock (shipped in `wordpress-plugin-workflows`), since `concurrency:` only serializes within one repo while every repo here has its own runner and they collide on wp-env's ports; and the reusable jobs' first step sets `core.hooksPath` to `/dev/null` globally, which `lefthook install` refuses to run against — that is why `prepare` skips when `CI` is set.

Versioning: the `version` field in `composer.json` is the single source of truth. `arts-wp` stamps it into the plugin header, `ARTS_CURSOR_FOLLOWER_PLUGIN_VERSION`, `readme.txt`, and `package.json` on every dev/build run — never hand-edit the version anywhere else. Browser providers read it through `constants/version.ts`; source consumers enable `resolveJsonModule`, and ESM builds inline it.

## Architecture

`src/ts/core/createCursor.ts` is the composition root that wires everything. The library surface is the package.json `exports` map: `src/ts/index.ts` (`createCursor`, `createCursorApp`), `contract.ts` (public types and constants) and `gateEntry.ts` (`/gate`). `src/ts/boot.ts` and `src/ts/gate.ts` are the two WordPress build entries (side-effect scripts bundled by `@arts/wp-plugin-tooling` (`arts-wp` — build/release/changelog/blueprint/doctor mechanics are documented in that package, not here)).

`createCursorApp({ options, signal })` (`createCursorApp.ts`) and `/gate`'s `createCursorGate({ css, load, js, editor })` (`createCursorGate.ts`) construct passive handles with explicit `init/destroy`. The app installs the stable discovery hub only on init. Gate `load(signal)` runs after CSS and must pass its captured signal to the deferred app; the classic WordPress path binds that same signal to `document.currentScript`. Never read the current gate's signal after a download: a newer gate may have replaced its owner. Gate/app disposal is terminal; direct engine `destroy/init` still supports reinitialization. Elementor kit changes reach the engine as an `arts-cursor:kit-change` window event dispatched by the editor bridge in `Plugin.php`; `boot.ts` is the only listener and binds it to the app signal.

**Loading model.** `src/ts/gate.ts` is the second build entry: a small pre-paint loader PHP prints inline on `wp_head` (nothing is enqueued on the front end). It installs `window.artsCursor` at parse, predicts the `<html>` classes from the shared `POINTER_MEDIA_QUERY`, injects the CSS `<link>` at parse when the query matches, and the engine `<script>` on the first mouse/pen `pointermove`, `wheel`, or media-query flip to matching (ids `arts-cursor-follower-for-elementor-css/-js`; the script waits for the CSS `onload`) — so touch devices download zero engine bytes. The CSS goes in at parse on purpose: the sheet carries `@layer arts-cursor` and two `@property` rules, and either one inserted after the page's first styles restyles the whole document (plus a full layout for the layer). On a large page that cost tens of milliseconds of style plus layout at the first mouse move when the CSS waited for it, and nothing extra at load when it doesn't. The first cursor the app publishes to the hub resolves its `ready` (late or never — never `null`); the Elementor preview loads immediately via the `editor` flag in `window.artsCursorFollowerBoot`. The printed gate tag carries NO id on purpose (ArtsAJAXTransitions syncs only id'd head scripts, re-evaluating one whose body changed; id-less ones are never touched), and the whole block is marked for cache-plugin opt-outs (the markers are listed in `Plugin::print_gate`).

**Frame path** (allocation-free by design — preallocated vectors mutated in place):
pointer input (`core/input.ts`, gated by a `(hover: hover) and (pointer: fine)` media query that owns listener lifecycle) → `IFrameState` (built by `core/frameState.ts`) → lerp + lag (`follower/pipeline.ts`) → elastic squash (`follower/elastic.ts`) → transform writer (`follower/transformWriter.ts`: one `transform` value mutated via CSS Typed OM, string fallback where Typed OM is missing), assembled by `follower/motion.ts`. `core/frameLoop.ts` owns the main cursor’s on-demand ticker subscription: geometry measurements → motion writes → idle reconciliation. Main motion sleeps once converged and wakes on pointer activity. Floating page-element effects are a separate consumer concern: `@arts/element-follower` lives in the Velum workspace and is neither imported nor bundled here. `cursor.stats` describes only this cursor. `suspendTargets()` owns a reference-counted pause of automatic target presentation; its completion waits for finite magnetic element returns (including the returning queue), never continuous following or explicit programmatic sessions. The last lease release schedules one hit-test from the core pointer coordinates.

**Two coordinate spaces — the core invariant.** Free-roam runs in viewport space (scroll never drags the cursor off the pointer). Magnetic engagement (`effects/magnetic.ts`) switches composition to page space, and scroll is subtracted at render time, outside the lerp — that is what keeps the cursor glued to its anchor while the page scrolls. Engage/release add/remove the scroll offset on `state.follower` so the space switch never jumps visually.

**Visual effects are a CSS state machine.** JS (`effects/suite.ts`) only flips `data-cursor-*` attributes and sets custom properties; all animation is CSS transitions inside the `arts-cursor` cascade layer (so unlayered theme CSS wins by default). Effect state is computed from layers: the transient hover payload at the bottom, programmatic sessions stacked above, last-wins per key; any layer change triggers one recompute of the merged payload — no sticky flags.

Supporting modules:
- `interaction/targets.ts` — delegated pointerover/out, one `resolveTarget()` pass shared by both handlers so enter and leave always compare the same element, per-element JSON payloads (`data-arts-cursor-follower-target`) parsed once into a WeakMap. A rule matched on an ancestor never outranks a target that is itself interactive (`a`, `button`, `[role="button"]`, opt-in class) — only a rule naming the element itself can claim it, else it gets the bare-interactive highlight; this is what keeps a carousel's track-wide drag rule off the links nested in its slides.
- `interaction/geometry.ts` — page-space element geometry with no layout flushes on interaction paths (IntersectionObserver revalidation, ResizeObserver, bounded observer-based idle pre-warm). Entries are stable objects mutated in place. One deliberate exception: magnetic engage calls `measure()` — a synchronous rect read — see Decided.
- `core/markup.ts` — build-or-verify markup: adopts existing `#arts-cursor` markup when present, otherwise builds the canonical tree (flat: every content part centers itself on the 0×0 wrapper anchor — no intermediary wrapper divs).

Injectables via `ICursorOptions`: `ticker` and `root`. `ITickerAdapter` is shape-compatible with `@arts/component-runtime`'s `ITicker` (same callback, same optional `priority`/`label`) — and with tempus only through `1.0.0-dev.17`, the version that package pins; tempus `1.0.0-dev.18` moved its callback to a single state object, so a newer tempus needs an adapter (see `TTickerCallback`). A host that owns the frame loop can share its ticker — obtainable from a foreign bundle as `window.__artsEngine__?.use(Symbol.for('engine/ticker'))`, the `Symbol.for` token identity being deliberate on that side. Only `deltaTime` and `frameCount` are portable across implementations: an injected ticker's `time` may count from its own clock epoch (tempus does), which is why `pipeline.frame` doesn't take it at all — `core/frameLoop.ts` drops it at the ticker boundary. It is also the seam the frame path is tested through — stepping an injected ticker makes frame-by-frame behavior deterministic. Discovery: the gate installs `window.artsCursor` at parse time and the app resolves its `ready` promise by publishing the cursor to that hub once `init()` completes — so on a touch-only device the global exists with a promise that never settles and a `get()` that stays null, because the gate never fetches the engine at all. A disabled request (or a deactivated plugin) prints no gate, so the global never appears. The engine also dispatches `arts-cursor:ready` on the document.

The docs site imports the engine only through the `@engine` alias (→ `src/ts/index.ts`) and styles through `@styles/*` — declared twice on purpose: tsconfig `paths` for the editor/typecheck, `docs/.vitepress/config.mts` for the browser build. Demo snippets in `docs/demos/` are single-sourced: the same file feeds the live render (`?raw` import) and the displayed code block (`<<<` include), and snippets show markup only — presentation lives in the theme's `demos.css`.

## Decided — don't reintroduce or "fix"

- WAAPI retargeting mode: rejected after a live feel comparison (rationale in the `follower/pipeline.ts` header).
- Magnetic engage measures fresh (`geometry.measure()` in `effects/magneticSessions.ts`, not `resolve()`): page-space coordinates are scroll-invariant only for in-flow elements — a fixed or stuck-sticky anchor (Velum's sticky-header burger) is stale by the whole scroll delta, which rendered the first engage frames toward the old position and inflated the release radius. Engage already flushes style via `getComputedStyle().transition`, so the one rect read there is deliberate — don't "optimize" it back to the cache.
- Magnetic `composeTarget` carries `state.follower` by the anchor's own frame-to-frame page-space delta BEFORE the lerp: a stuck-sticky anchor travels through page space at scroll speed, and lerping that trailed the ring ~4× the scroll speed behind a stationary chevron (Velum's scroll-driven sliders, 1.2 s Lenis travel: ~220 px). In-flow anchors have delta 0 and keep the render-time scroll glue; don't drop the carry or move the glue into the lerp.
- `linear()` easing token: deliberately a cubic-bezier back-out instead — an unsupported easing arriving through `var()` silently kills the whole transition.
- **Two easing curves, not one.** `--arts-cursor-collapse-ease` is the back-out with the back removed (same x-timing, y flattened 1.56 → 1), and it exists because the back-out peaks at ~1.098: a `scale` transition to a target of exactly 0 interpolates `S * (1 - f(t))`, which goes NEGATIVE the moment `f(t) > 1`, and `scale` — unlike `opacity` or `width` — has no clamp, so the element mirrors back into view instead of hiding (measured: min −0.097, a 5.8px flipped ring for ~130ms of the 250ms). Don't collapse the two curves back into one, and don't reach for `scale: max(0, …)` — math functions resolve at computed-value time on the endpoints, so the overshoot is applied afterwards, unclamped. Which curve applies is pure CSS: a transition takes its timing function from the **after-change style**, so the collapsed-state rule carries `$motion-collapse` and the expanded-state rule carries `$motion`, and the direction switch costs no JS. For the wrapper and the press dot the collapsed state IS the base rule; the follower needs `data-cursor-collapsed` (`effects/suite.ts`, on `scale === 0`) only because its zero arrives as a number in a custom property and no selector can read one.
- The six public theming vars (`--arts-cursor-size`, `-text-color`, `-loading-color`, `-border-width`, `-border-color`, `-background-color`) are deliberately NOT registered via `@property` — registration would give them permanent initial values and silently disable the `var(--x, fallback)` theming pattern the styles are built on.
- Cross-navigation position restore: dropped.
- The scroll offset comes from `window` and nothing else — don't add a `scrollSource` injectable. `interaction/geometry.ts` derives page coordinates as `rect + window.scroll`, and the frame path subtracts `state.scroll` (a plain field `core/frameState.ts`'s `createScrollReader` keeps current by sampling `window` on a passive `scroll` listener — seeded once, re-synced authoritatively at engage and snap — so no per-frame `window.scrollX` forces layout; that listener is the same `window` sampled at a different moment, not a second source). A second source can only disagree with the first, and a rect already reflects the *applied* scroll. `@arts/smooth-scrolling` runs Lenis in native mode (`wrapper`/`content` never overridden, so it writes real `window.scrollTo` every frame), and there are no plans to support scroll-hijacking libraries that would need an adapter.
- `import.meta.env?.DEV` uses optional access on purpose: Vite defines it in the docs site, esbuild `define` substitutes it in plugin builds, `?.` keeps it safe in any bundler without the define.
- Splitting `src/ts/core/options.ts`: `fallow health --targets` recommends it on churn × fan-in and will keep doing so. Rejected — the file exists precisely so each default is stated once and shared by the initial resolve and the live patch. Its dependent count is also inflated by the test files that import `resolveOptions` to build fixtures. `fallow health` has flagged `core/input.ts` on the same churn × fan-in heuristic — same rejection if it resurfaces (a tiny file, and `accepts` belongs next to the listeners it gates).
- Splitting `effects/suite.ts`: the pure deciders and the applier co-evolve (a new payload key touches both), and the test tiers already split along the seam (`suite.test.ts` node / `suite.dom.test.ts` dom). Extract an over-threshold decider to module scope when fallow flags one (`arrowOnlyPill` is the worked example) — don't split the file. Revisit only if it keeps growing.
- **`hint` vs `label` is a deliberate split, not drift.** `label` is the payload key holding the TEXT; `hint` is the thing the cursor becomes while showing content. So `data-cursor-hint` is raised for an icon-only payload too, `--arts-cursor-hint-*` styles the pill/circle/icon alike, and `.arts-cursor__hint` contains `__hint-text` and `__hint-icon`. Names that stay `label` on purpose: the payload key, the per-element wording vars `--arts-cursor-{drag,media,box,image,card,container}-label` and their controls, `sanitize_hint_label`, `readCssLabel`/`labelVar`, the `'label'` enum value meaning "text not icon" in the Content chooser, and the unrelated ticker `label` option.
- The standalone icon (`className` payload key → `.arts-cursor__icon` → `data-cursor-icon`) was deleted pre-1.0: fully implemented and unit-tested, but never used by `Options.php`, `WidgetControls.php` or any demo, and no shipped CSS gave that element visible content. Icons ride the hint's icon slot (`icon`/`iconClass`/`iconUrl`) — don't add a second icon channel back.
- `highlight.opacity`: rejected, not merely unimplemented. `.arts-cursor__follower` is a leaf (arrows/hint/dot/spinner are its siblings), so element opacity could only touch its own fill and border — which two rgba controls already do independently, and `background-color`/`box-shadow` are already in its transition list while `opacity` is not. A single opacity knob would be strictly less expressive.
- One Site Settings section per visual state. "Text Hints" and "Icon Hints" were merged into **Hints** because they weren't peers: a hint can be text AND icon at once (`data-cursor-icon-kind` means "has an icon", not "is an icon"), so the second section was a base+override pair whose 8 duplicated controls wrote the *same* vars one attribute tighter — invisible inheritance Elementor can't render for sliders or colors. Per-icon styling stays reachable in CSS via `.arts-cursor[data-cursor-icon-kind]`.
- `data-cursor-shape-axis` keeps `'x'|'y'` while `arrows` keeps `'horizontal'|'vertical'` — different questions (which dimension the pill's box stretches vs which arrow pair the author asked for), consumed by disjoint code. Unifying the spelling would imply a relationship that isn't there.
- The cursor over an `<iframe>`: the parent document goes blind while the pointer is INSIDE one — over a cross-origin embed (YouTube/Vimeo/Maps) no pointer events and no `:hover` reach the parent (verified live; only `elementFromPoint` still resolves it). What ships rides the one observable signal instead: the crossing INTO the frame is the last parent-side event and `pointerover` targets the iframe element, so `resolveTarget` returns null for an iframe (no rule may hold, `refresh()` included) and the move gate in `createCursor.ts` folds the engine back to the not-yet-seen state — the ring collapses away and re-materializes at the pointer on the next parent-side event, like page entry. The rejected workarounds stay rejected: an overlay injects DOM over third-party embeds and blocks their interaction; a geometry/idle watchdog is heuristic and misses fast flicks; `pointer-events: none` kills interaction. Don't "upgrade" this to tracking or restoring within the frame — nothing is observable in there, and hiding is also the honest answer (the embedded document owns the native cursor over its own pixels; anything we drew there would be a second cursor).

## Elementor integration — landmines (verified in source; don't re-derive)

Each of these cost real debugging time and none of them fails loudly. `src/php/Elementor/WidgetControls.php` injects the per-widget "Cursor Effects" section; `Options::build()` holds the selector→effect rules.

- **Per-instance data reaches the cursor as a marker class or a CSS var — never an attribute.** Neither editor render path populates `_wrapper` (the JS-template path builds the outer node client-side; the AJAX path renders through `render_content()`, never `print_element()`), so a PHP-printed attribute is correct on the front end and invisible in the preview. Enable/disable therefore *must* be a class (it has to participate in a selector the engine matches with `closest()`); text and icons *must* be a var via `selectors`.
- **Nothing riding `selectors` may contain a `;`.** Elementor splits every declaration block on `;` and silently discards the **whole block** as soon as a fragment has no `:` left in it (`Stylesheet::add_rules`) — no warning, no partial output, the widget's rule simply never gets written. A base64 data URI carries `;base64` in its own header, which is why the icon SVG is `rawurlencode`d (`inline_font_icon_svg`), and why typed hint text has `;`, `"` and `\` stripped (`sanitize_hint_label`). Blast radius is one `add_rules` call, so neighbouring controls survive — but anything we ever put through `selectors` has to clear this.
- **A CSS escape is not the way around it**: `getComputedStyle` returns `"a\3B b"` with the escape **unresolved**, so the cursor would render the escape sequence itself. Strip, don't escape.
- **`get_controls()` with no id hides most controls that carry `selectors` outside the editor.** They're diverted to a separate `style_controls` bucket whenever `Performance::should_optimize_controls()` — which is just `! is_admin() && ! is_preview_mode() && ! REST_REQUEST`, i.e. *always* on the front end, gated by no experiment. So a front-end probe reporting a control as "not registered" proves nothing; flip `Performance::set_use_style_controls( true )` around the read first.
- **Verify every selector against the RENDERED front-end page, not the widget source.** `.elementor-clickable` is the standing example: Image and Media Carousel both add it only under `is_edit_mode()`, so a rule keyed on it matches in the preview and never once on a real page.
- **A widget's "last Style section" is a byproduct, not a contract** — `start_injection()` re-splices the controls array, so the section registered last in source routinely isn't last in the stack. Measure it off the registered stack (iterate `get_controls()` for `type === 'section'`, ignore the `_section_*` Advanced ones); reading Pro's Testimonial Carousel source puts its last section one place too early.
- **We never enqueue Font Awesome** — Elementor does it for us because ours is an ICONS control (its `icons_fonts[]` bookkeeping fires on control TYPE, before the `selectors` check). The one gap: with `e_font_icon_svg` active it stops loading the webfont on the **front end only**, which is exactly what the data-URI channel in `inline_font_icon_svg()` covers. Both states are verified live.

## Conventions

- Formatting is Biome's: 2-space indent, single quotes, no semicolons, no trailing commas, 100-col lines.
- Commits: `type(scope): lowercase summary` (`feat(cursor):`, `fix(magnetic):`, `docs:`, `ci:`, `chore(deps):`; a bare domain prefix like `engine:` also appears in history), body in prose explaining why.
- TypeScript is `strict` + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes` (several internal records are typed required-but-possibly-undefined to forward optional fields verbatim — see `ICompiledRule`); the default package types are emitted declarations, and `arts-source` selects the shipped TypeScript (`src/ts/index.ts`, `contract.ts`, `gateEntry.ts`).
- Pure module-scope helpers are exported even when nothing in the repo imports them (`resolveAppearance`, `parsePayload`, `ruleEnabled`, `writeEntry`, …). They are the unit-test surface, not dead code — don't "clean them up" as unused. A module export is internal by convention; the package's public API is whatever the three `exports` entries (`index.ts`, `contract.ts`, `gateEntry.ts`) re-export.
- Tests live in `tests/ts/`, a tree mirroring `src/ts`, not colocated — colocation doubles every source folder's listing. They import the engine through the `@ts/*` alias (tsconfig `paths` + vitest `resolve.alias`), plus shared fixtures from `tests/ts/support.ts` relatively. The alias is TEST-ONLY: a `@ts/` import inside `src/ts` would force the mapping onto every consumer compiling the source (Velum does), which is why `tests/ts/aliasBoundary.test.ts` greps the shipped tree and fails the suite on the first leak. Tests are typechecked (`tsconfig.json` `include`) and Biome-checked (`files.includes`), and never shipped (release staging copies `src/wordpress-plugin` (flattened to the package root), `src/php`, the composer manifest and the two vendor trees; esbuild bundles from `boot.ts`).
- Test conventions: import from `vitest` explicitly rather than enabling globals, so `types` stays `["node"]` (set in the shared `@arts/wp-plugin-tooling/tsconfig` base this repo extends, not in `tsconfig.json` itself). Fake collaborators with plain object literals, not a mocking library — the engine never uses `instanceof` (that is what `utils/isElement.ts` is for), so `{ nodeType: 1, closest: () => null }` is a legitimate Element to every consumer, and a `{ resolve: vi.fn() }` is a legitimate geometry cache. Name each `it` after the rule it protects. Copy vectors into a fake state rather than aliasing a shared literal: the frame path mutates `state.lag`/`state.follower` in place, so an aliased fixture leaks across tests.
- `tests/ts/phpDefaultsParity.test.ts` is the one test that reads PHP: it regex-parses `Options::build()`'s `size_of()` fallbacks and `is_on()` defaults and asserts they equal `constants/defaults.ts`. The two languages share no build step, and a default changed on one side only ships as "the editor preview disagrees with the published page" — PHPStan is type analysis and can't see a value drift, and nothing else in the suite opens a `.php` file. So **changing a default in `Options.php` means changing `defaults.ts` in the same commit**, or this fails. It parses rather than executes on purpose: booting WordPress for a handful of numbers isn't worth a PHP runtime in the suite.
- `coverage.include` is set explicitly in the shared Vitest config (`@arts/wp-plugin-tooling/vitest` — `vitest.config.ts` only calls it) because v4 removed `coverage.all` and otherwise reports only files touched by a run — an untested module would be absent rather than showing as 0%. No thresholds — the few remaining uncovered branches are type-mandated guards unreachable by construction, and the visible behavior lives in the CSS state machine and real layout that coverage cannot measure, so a percentage gate would enforce nothing useful.
- Test environment: default to `node` and opt individual files into `happy-dom` with a `// @vitest-environment happy-dom` docblock. happy-dom has `matchMedia`, `ResizeObserver` and `IntersectionObserver` and reports `(hover: hover) and (pointer: fine)` as matching, so the engine boots enabled (the shared Vitest config records why jsdom is not used). Most of the engine — the frame path apart from the transform writer, options, the scale grammar, the pure deciders — needs no DOM at all, and a `node` default makes an accidental `document` reach fail loudly instead of passing against a fake.
- Two tiers, and the environment is per FILE, so a module with both gets two: `x.test.ts` holds the pure deciders under `node`, `x.dom.test.ts` the stateful/applier half under `happy-dom` (`effects/suite` is the model). A module that is DOM-only end to end keeps one `.dom.test.ts` carrying the docblock; one that needs no DOM at all (options, the scale grammar, most of the `follower/` frame path, `utils/*`) keeps one `node` file. Don't merge a pure file into its DOM sibling to save a file — that is exactly the `node` guard above being thrown away.
- `import.meta.env.DEV` is forced **false** for tests by `tests/ts/setup.ts` (`vi.stubEnv`), so the dev-only branches — `parsePayload`'s `console.debug`, `ref()`'s missing-markup warn, `warnIfContainingBlockHijacked`'s deferred rAF, the frame timing in `follower/motion.ts` — do not run, and the suite exercises the code that ships. A `define` cannot do this job: Vitest ignores a `define` of `import.meta.env.DEV` (plain member or optional chain alike), so one in `vitest.config.ts` would silently do nothing (esbuild *does* substitute the optional chain, which is why the plugin bundle is unaffected either way). The tests that cover those branches flip it back with `vi.stubEnv('DEV', true)` for their own scope and restore false afterwards; everything else runs the shipped path.
- Don't add injectables for what a test can stub. `createGeometryCache` constructs its own `ResizeObserver`/`IntersectionObserver` on purpose: `vi.stubGlobal` with a fake that captures the callback drives records synchronously, which is what makes eviction, streaming re-observe and the resize debounce assertable. Same for the ticker's rAF, and for the suite's base size (`offsetWidth` is 0 in every non-browser DOM, so scales resolve against `BASE_SIZE_FALLBACK` unless the test defines the property). Injected observers could not desync anything the way `scrollSource` could, but they would still be configurability nobody asked for.
- Unit tests structurally cannot reach real layout and hit-testing (every rect is 0×0) or the CSS state machine that owns most of the visible behavior; the docs site (`pnpm dev`) is the harness for them. The CSS Typed OM branch in `follower/transformWriter.ts` sits near that line: happy-dom does not implement it, so the suite drives it through stub constructors that reproduce the CSSMatrixComponent copy trap, and the docs site remains the check against the real API (the matrix math and dedupe are shared with the string fallback — don't extract them, it would allocate on the frame path).
- Interfaces, type aliases, and constants live in dedicated folders (`src/ts/interfaces`, `src/ts/types`, `src/ts/constants`) — one declaration per file, `I`-prefixed interfaces, `T`-prefixed types, each folder with an `index.ts` barrel. Modules import them back through the barrel (`../interfaces`, `../types`, `../constants`); `src/ts/contract.ts` re-exports the public names. Interface files import other declaration files directly (`./IX`, `../types/TX`), never through the barrels — `types/TBootOptions` already reaches `interfaces/index`, so routing `interfaces/ → ../types` through the barrel would close a `types/index ↔ interfaces/index` cycle; the barrel rule applies to consumer modules. The ambient global augmentations keep their exact built-in names, not `I`-prefixed (prefixing breaks declaration merging): `Window` in `global.d.ts`, `ImportMeta` in `env.d.ts`, `SymbolConstructor` co-located with its consumer in `interfaces/ICursorSession.ts`.

## Host-controlled drag presentation

Payload `dragMode: 'controlled'` opts out of automatic drag recognition; the default `auto` preserves existing sites. `bindDrag(target, { getState })` returns `refresh()` / `release()`. The host supplies `idle | pressed | dragging | rejected | unavailable` and refreshes on changes. Unbound controlled targets stay neutral. `interaction/controlledDrag.ts` owns only the hover/press presentation and holds rejection across target crossings until release; unrelated programmatic sessions keep their precedence. `IEffectsSuite.setPressed` is the event-independent press reset, including both native-cursor hiding mechanisms.
